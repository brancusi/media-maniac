# Pipeline Concept

A **pipeline** is the central abstraction in Media Maniac for processing a source media file through a series of steps. Each step is called a **process**. Processes form a **directed acyclic graph (DAG)** — some can run in parallel, others must wait for dependencies to finish first.

![pipeline-concept.svg](../diagrams/pipeline-concept.svg)

---

- ## Data Model

  Two XTDB v2 tables back the pipeline system:

  | Table        | Purpose                                                                                               |
  | ------------ | ----------------------------------------------------------------------------------------------------- |
  | `:pipelines` | One row per pipeline — holds the UUID and source file path                                            |
  | `:processes` | One row per processing step — holds type, options, status, deps, and a back-reference to its pipeline |

- ### Malli Schemas

  Defined in [`bases/grand-central/src/com/atd/mm/grand_central/model/specs.clj`](../../bases/grand-central/src/com/atd/mm/grand_central/model/specs.clj):

  ```clojure
  (def ProcessDefinition
  [:map
   [:xt/id :uuid]
   [:status [:enum :open :processing :completed]]
   [:opts {:optional true} :map]
   [:type [:enum :media/proxy
           :media/extract-audio
           :media/extract-stills
           :media/transcribe
           :media/copy]]
   [:deps {:optional true} [:vector :uuid]]])

  (def Pipeline
  [:map
   [:xt/id :uuid]
   [:src :string]
   [:processes {:optional true} [:vector #'ProcessDefinition]]])
  ```

  **Key fields on a process:**

- **`:xt/id`** — UUID, primary key in XTDB
- **`:type`** — what kind of media operation (`:media/proxy`, `:media/extract-stills`, etc.)
- **`:status`** — lifecycle state: `:open` → `:processing` → `:completed`
- **`:deps`** — a vector of UUIDs pointing to other processes that **must complete** before this one can run
- **`:opts`** — a free-form map of options specific to the process type (resolution, encoding, frequency, etc.)
- **`:pipeline-id`** — back-reference UUID linking this process to its parent pipeline

  ***

- ## How a Pipeline Gets Created

  There are three phases: **define → prepare → persist**.

- ### Phase 1: Define the pipeline

  You start with a plain map describing the source file and a vector of processes with human-readable string IDs. Dependencies reference those string IDs:

  ```clojure
  ;; From bases/grand-central/src/com/atd/mm/grand_central/fiddle.clj

  {:src "/footage/A001_C003.MP4"
  :processes [{:xt/id "proxy-720"
              :status :open
              :type :media/proxy
              :opts {:size 720}}

             {:xt/id "extract-audio"
              :status :open
              :type :media/extract-audio
              :opts {:encoding "wav"}}

             {:xt/id "extract-stills"
              :status :open
              :type :media/extract-stills
              :opts {:frequency 10}
              :deps ["proxy-720"]}          ;; ← depends on proxy

             {:xt/id "transcribe"
              :status :open
              :type :media/transcribe
              :opts {:model :whisper}
              :deps ["proxy-720"             ;; ← depends on BOTH
                     "extract-audio"]}

             {:xt/id "copy"
              :status :open
              :type :media/copy
              :opts {:dest "/archive"}}]}
  ```

  At this stage the IDs are strings and the data hasn't been validated or stored anywhere.

- ### Phase 2: Prepare the pipeline (`prepare-pipeline`)

  The `prepare-pipeline` function in [`components/media-converter/src/com/atd/mm/media_converter/pipeline.clj`](../../components/media-converter/src/com/atd/mm/media_converter/pipeline.clj) transforms the human-readable definition into a database-ready structure:

  ```clojure
  (require '[com.atd.mm.media-converter.interface :as media-converter])

  (media-converter/prepare-pipeline raw-pipeline)
  ```

  **What `prepare-pipeline` does:**
  1. **Generates a pipeline UUID** — `(java.util.UUID/randomUUID)` for the pipeline's `:xt/id`
  2. **Replaces string IDs with UUIDs** — each process's `:xt/id` like `"proxy-720"` becomes a real UUID
  3. **Updates dependency references** — any `:deps` entries that pointed to old string IDs now point to the corresponding new UUID. This uses [Specter](https://github.com/redplanetlabs/specter) for deep structural transforms:

  ```clojure
  (defn- update-process-deps
    [data old-id new-id]
    (setval [(filterer #(:deps %))
             ALL :deps
             (filterer #(= % old-id))
             ALL]
            new-id
            data))
  ```

  4. **Stamps every process with `:status :open`** — all processes start in the open state
  5. **Stamps every process with `:pipeline-id`** — back-reference to the parent pipeline UUID

  **Example output after preparation:**

  ```clojure
  {:xt/id #uuid "03e1545e-f6d0-4b02-a1f2-b466f87a9394"   ;; pipeline UUID
  :src "/footage/A001_C003.MP4"
  :processes
  [{:xt/id #uuid "a1b2c3d4-..."
   :type :media/proxy
   :opts {:size 720}
   :status :open
   :pipeline-id #uuid "03e1545e-..."}

  {:xt/id #uuid "e5f6a7b8-..."
   :type :media/extract-audio
   :opts {:encoding "wav"}
   :status :open
   :pipeline-id #uuid "03e1545e-..."}

  {:xt/id #uuid "c9d0e1f2-..."
   :type :media/extract-stills
   :opts {:frequency 10}
   :deps [#uuid "a1b2c3d4-..."]            ;; ← now a real UUID
   :status :open
   :pipeline-id #uuid "03e1545e-..."}

  {:xt/id #uuid "11223344-..."
   :type :media/transcribe
   :opts {:model :whisper}
   :deps [#uuid "a1b2c3d4-..."             ;; proxy UUID
          #uuid "e5f6a7b8-..."]            ;; extract-audio UUID
   :status :open
   :pipeline-id #uuid "03e1545e-..."}

  {:xt/id #uuid "55667788-..."
   :type :media/copy
   :opts {:dest "/archive"}
   :status :open
   :pipeline-id #uuid "03e1545e-..."}]}
  ```

- ### Phase 3: Persist to XTDB (`create-pipeline`)

  The `create-pipeline` function in [`bases/grand-central/src/com/atd/mm/grand_central/model/pipeline.clj`](../../bases/grand-central/src/com/atd/mm/grand_central/model/pipeline.clj) validates and stores the pipeline.

  ```clojure
  (require '[com.atd.mm.grand-central.model.pipeline :as pipeline])

  (pipeline/create-pipeline prepared-pipeline)
  ```

  Here is **exactly** what happens inside `create-pipeline`:

  ```clojure
  (defn create-pipeline
  [pipeline & {:keys [xtdb-node]}]

  ;; 1. Validate the entire structure against the Malli schema
  (when-not (pipeline-valid? pipeline)
    (throw (ex-info "Not a valid pipeline"
                    {:pipeline pipeline
                     :explanation (explain-invalid-pipeline pipeline)})))

  ;; 2. Split the data for two separate XTDB tables
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))
        processes-tx-data (:processes pipeline)              ;; vector of process maps
        pipeline-tx-data {:xt/id (:xt/id pipeline)           ;; just the pipeline shell
                          :src (:src pipeline)}]

    ;; 3. Submit a SINGLE atomic transaction with TWO operations:
    (xt/submit-tx xtdb-node
      [(into [:put-docs :processes] processes-tx-data)       ;; op 1: bulk insert processes
       [:put-docs :pipelines pipeline-tx-data]])))           ;; op 2: insert pipeline row
  ```

  **This is critical to understand — the data is split across two tables in a single atomic transaction:**

- #### XTDB Transaction Breakdown

  The `xt/submit-tx` call receives a vector of transaction operations. Each operation is itself a vector:

  **Operation 1: Insert all processes into the `:processes` table**

  ```clojure
  (into [:put-docs :processes] processes-tx-data)
  ```

  This expands to:

  ```clojure
  [:put-docs :processes
  {:xt/id #uuid "a1b2c3d4-..."
   :type :media/proxy
   :opts {:size 720}
   :status :open
   :pipeline-id #uuid "03e1545e-..."}
  {:xt/id #uuid "e5f6a7b8-..."
   :type :media/extract-audio
   :opts {:encoding "wav"}
   :status :open
   :pipeline-id #uuid "03e1545e-..."}
  ;; ... all other processes
  ]
  ```

  XTDB v2's `:put-docs` accepts a table name followed by one or more document maps. Each document **must** have an `:xt/id` field. All five processes are inserted into the `:processes` table in a single operation.

  **Operation 2: Insert the pipeline record into the `:pipelines` table**

  ```clojure
  [:put-docs :pipelines {:xt/id #uuid "03e1545e-..."
                       :src "/footage/A001_C003.MP4"}]
  ```

  The pipeline record is intentionally lean — it only stores the UUID and source path. The processes are linked back via their `:pipeline-id` field.

  **Both operations execute atomically.** Either all processes and the pipeline row are committed, or none are. There is no intermediate state where processes exist without their parent pipeline.

- ## Dependency Resolution: How Scheduling Works

  Once a pipeline is persisted, the scheduler needs to determine which processes are **ready to run**. A process is ready when:
  1. Its `:status` is `:open`
  2. It has **no** `:deps`, OR **all** processes in its `:deps` vector have `:status :completed`

  This logic lives in [`bases/grand-central/src/com/atd/mm/grand_central/model/process.clj`](../../bases/grand-central/src/com/atd/mm/grand_central/model/process.clj):

- ### The query: `get-ready-to-process`

  ```clojure
  (defn get-ready-to-process
  [& {:keys [xtdb-node]}]
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))
        open-processes (xt/q xtdb-node
                         '(-> (from :processes [{:status :open} *])
                              (with {:deps (pull* (fn [deps]
                                                    (->
                                                     (unify (from :processes [{:xt/id dep-id} status])
                                                            (unnest {dep-id deps})))))})))]
    (filter all-process-deps-completed? open-processes)))
  ```

  **Step by step:**
  1. **`(from :processes [{:status :open} *])`** — Query all processes where `:status` is `:open`. The `*` means return all columns.
  2. **`(with {:deps (pull* ...)})`** — For each open process, **replace** the `:deps` field (which is just a vector of UUIDs) with the **actual status of each dependency**. The `pull*` subquery:
  - Takes the process's `:deps` vector
  - `unnest`s it into individual `dep-id` values
  - Joins back to the `:processes` table to fetch each dependency's current `:status`
  - Returns a vector like `[{:dep-id #uuid "...", :status :completed}, {:dep-id #uuid "...", :status :open}]`
    3.  **`(filter all-process-deps-completed? ...)`** — Clojure-side filtering. Only keep processes where every dep has `:status :completed`:

    ```clojure
    (defn process-completed? [process]
    (= (:status process) :completed))

    (defn all-process-deps-completed? [process]
    (every? process-completed? (:deps process)))
    ```

- ### Example: Dependency resolution over time

  Given the 5-process pipeline above, here's how scheduling unfolds:

  **Cycle 1** — Initial state, all processes are `:open`:

  | Process        | Deps                       | Deps Status    | Ready?  |
  | -------------- | -------------------------- | -------------- | ------- |
  | proxy-720      | none                       | —              | **YES** |
  | extract-audio  | none                       | —              | **YES** |
  | copy           | none                       | —              | **YES** |
  | extract-stills | [proxy-720]                | [:open]        | no      |
  | transcribe     | [proxy-720, extract-audio] | [:open, :open] | no      |

  The scheduler picks up `proxy-720`, `extract-audio`, and `copy`. They get queued as Goose jobs.

  **Cycle 2** — After proxy-720 and extract-audio complete:

  | Process        | Deps                       | Deps Status              | Ready?  |
  | -------------- | -------------------------- | ------------------------ | ------- |
  | extract-stills | [proxy-720]                | [:completed]             | **YES** |
  | transcribe     | [proxy-720, extract-audio] | [:completed, :completed] | **YES** |

  Both blocked processes are now eligible. The scheduler queues them.

  **Cycle 3** — All processes completed. Pipeline is done.

- ### Updating process status

  After a worker finishes executing a process, its status is updated via `patch-docs`:

  ```clojure
  (defn update-process
  [id patch & {:keys [xtdb-node]}]
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))]
    (xt/submit-tx xtdb-node
      [(into [:patch-docs :processes]
             [(merge patch {:xt/id id})])])))

  ;; Example: mark a process as completed
  (update-process #uuid "a1b2c3d4-..." {:status :completed})
  ```

  The `:patch-docs` operation is a **partial update** — it only modifies the fields you pass, leaving everything else unchanged. This is more efficient than re-writing the entire document.

- ## Querying Pipelines from XTDB
- ### Get a single pipeline with all its processes

  [`pipeline.clj`](../../bases/grand-central/src/com/atd/mm/grand_central/model/pipeline.clj) uses XTQL's `pull*` to reconstruct the full pipeline:

  ```clojure
  (defn get-pipeline [id & {:keys [xtdb-node]}]
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))
        query ['(fn [id]
                  (->
                   (from :pipelines [{:xt/id id} *])
                   (with {:processes (pull* [(fn [id]
                                               (-> (from :processes
                                                         [{:pipeline-id id} *])))
                                             id])})))
               id]]
    (first (xt/q xtdb-node query))))
  ```

  This returns a single map with nested processes:

  ```clojure
  {:xt/id #uuid "03e1545e-..."
  :src "/footage/A001_C003.MP4"
  :processes [{:xt/id #uuid "a1b2c3d4-..."
              :type :media/proxy
              :status :completed
              :pipeline-id #uuid "03e1545e-..."
              :opts {:size 720}}
             ;; ... other processes
             ]}
  ```

- ### Get all pipelines

  ```clojure
  (defn get-all-pipelines [& {:keys [xtdb-node return]}]
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))
        query (seq (cond-> ['->
                            '(from :pipelines [{:xt/id pipeline-id} *])
                            '(with {:processes (pull* (fn [pipeline-id]
                                                        (-> (from :processes
                                                                  [{:pipeline-id pipeline-id} *]))))})]
                     return (conj return)))]
    (xt/q xtdb-node query)))
  ```

- ### Delete a pipeline (cascading)

  Deleting a pipeline removes both the pipeline row and all its processes atomically:

  ```clojure
  (defn delete-pipeline [id & {:keys [xtdb-node]}]
  (let [xtdb-node (or xtdb-node (resolver/get-xtdb-node))
        pipeline (get-pipeline id)
        process-ids (select [:processes ALL :xt/id] pipeline)]
    (xt/submit-tx xtdb-node
      [(into [:delete-docs :pipelines] [(:xt/id pipeline)])
       (into [:delete-docs :processes] process-ids)])))
  ```

- ## Full End-to-End Example

  ```clojure
  (require '[com.atd.mm.media-converter.interface :as mc])
  (require '[com.atd.mm.grand-central.model.pipeline :as pipeline])
  (require '[com.atd.mm.grand-central.model.process :as process])

  ;; 1. Define
  (def raw {:src "/footage/A001_C003.MP4"
          :processes [{:xt/id "proxy-720"
                       :status :open
                       :type :media/proxy
                       :opts {:size 720}}
                      {:xt/id "extract-stills"
                       :status :open
                       :type :media/extract-stills
                       :opts {:frequency 10}
                       :deps ["proxy-720"]}]})

  ;; 2. Prepare (string IDs → UUIDs, stamp pipeline-id)
  (def prepared (mc/prepare-pipeline raw))

  ;; 3. Validate
  (pipeline/pipeline-valid? prepared)  ;; => true

  ;; 4. Persist to XTDB (atomic: pipeline + all processes)
  (pipeline/create-pipeline prepared)

  ;; 5. Query what's ready to run
  (process/get-ready-to-process)
  ;; => [{:xt/id #uuid "a1b2c3d4-..." :type :media/proxy ...}]
  ;;    (only proxy-720 — extract-stills is blocked)

  ;; 6. After proxy-720 completes, mark it done
  (process/update-process #uuid "a1b2c3d4-..." {:status :completed})

  ;; 7. Query again — extract-stills is now unblocked
  (process/get-ready-to-process)
  ;; => [{:xt/id #uuid "c9d0e1f2-..." :type :media/extract-stills ...}]
  ```
